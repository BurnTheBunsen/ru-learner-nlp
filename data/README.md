# data/

## framebank/  (confirmed as of this writing)

Contains the Russian FrameBank offline dictionary release
(github.com/olesar/framebank), used by `src/adapters/framebank_adapter.py`
to look up expected case/preposition patterns for Russian verbs.

Required file: `framebank_dict_cx_items.txt`.
`framebank_dict_cx.txt` is downloaded alongside it but not currently used
by the adapter (see that file's module docstring).

**Not committed to git** (GPL-3.0-licensed third-party data, same
treatment as the UDPipe model and Mystem binary -- large external
resources referenced by path/env var, not checked in). To reproduce:

```
git clone https://github.com/olesar/framebank
# or download framebank_dict_cx_items.txt directly from that repo
```

A derived, filtered `framebank_valency.json` (just the verb lemmas this
project's corpus actually uses, pre-processed into a smaller project-
specific schema) is the eventual planned artifact here -- small enough,
and different enough from the raw dictionary, to be worth committing
once `pipeline/extraction_runner.py` exists and the real corpus's verb
usage is known. Not built yet.

## raw/  (per architecture.txt -- confirm this matches reality)

Original cross-sectional learner essays. Not committed (learner writing
samples; check with advisor/IRB before ever considering this).

## gold_standard/  (per architecture.txt -- confirm this matches reality)

Manually annotated data (character spans) for evaluation against the
pipeline's output. Provenance/tracking status TBD.

## processed/  (per architecture.txt -- confirm this matches reality)

Pipeline output:
- `tier1_token.csv` -- token-level forensics (Target/Boundary overlap)
- `tier2_essay.csv` -- essay-level aggregates (E_case, E_aspect per 1k)

Generated by `pipeline/extraction_runner.py` (not yet built). Not
committed -- regenerable from raw/ + the pipeline code.

---

**Note:** this structure uses `data/framebank/` rather than the
`data/resources/framebank_valency.json` path originally sketched in
`architecture.txt`. Worth updating that doc to match, since FrameBank
turned out to need its own subfolder (multiple raw files, not a single
resource file) rather than fitting the generic "resources" bucket.
